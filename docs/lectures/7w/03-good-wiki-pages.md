# 3. 좋은 위키 문서 — 출처, 다시 쓰는 구조, 연결

[목차](README.md) · 이전: [폴더 구조](02-folder-structure.md) · 다음: [복습과 실습](04-review-and-practice.md)

> 원전 대응: 2.3 좋은 위키 문서의 조건.[6]

## 3.1 글이 매끄러운 것과 믿고 쓸 수 있는 것은 다르다

“AI로 회의록을 정리하면 아주 좋다”라는 문장은 읽기 쉽다. 하지만 근거가 무엇인지, 언제 쓸 수 있는지, 다음에 무엇을 확인해야 하는지 알 수 없다.

원전은 좋은 위키 문서의 조건을 **출처가 남는 문서, 질문에 다시 쓰기 쉬운 문서, 링크로 이어지는 문서**로 설명한다.[6]

쉽게 말하면 정리 노트에 다음을 붙이는 것이다.

1. **어디서 알았는지 표시하기.**
2. **다음 질문에도 쓸 수 있게 칸을 나누기.**
3. **더 읽을 곳으로 가는 길 붙이기.**

## 3.2 조건 1 — 출처: “어디에 그렇게 쓰여 있지?”

출처는 문서의 장식이 아니라 확인하는 방법이다. 중요한 주장에 원천 자료의 경로·URL·확인 날짜 등을 연결한다.[6]

원문 안의 절이나 항목까지 표시하면 어떤 부분을 대조할지 더 분명해진다. 이것은 수업에서 덧붙이는 작성 팁이다.

| 약한 표현 | 근거를 확인할 수 있는 표현 |
| --- | --- |
| AI를 도입하기로 했다. | 가상 회의 메모에는 활용 검토 제안이 있다. 결정 여부는 확인 필요다. |
| 정리 시간이 크게 줄었다. | 시간 절약 정도는 아직 측정하지 않았다. |
| 규칙상 안전하다. | 처리 기준은 적었지만 실제 입력과 결과는 별도로 점검해야 한다. |

표는 앞선 가상 팀 회의 사례의 연습이다. 출처를 붙인다고 근거보다 강한 결론을 써도 되는 것은 아니다.

최소한 **원천 자료·자료 성격·확인 날짜·확인 필요**를 알아볼 수 있어야 한다.[6]

## 3.3 조건 2 — 재사용: “이 노트로 다음에 무엇을 물을까?”

재사용은 같은 글을 여러 번 복사하는 것이 아니다. 정리된 내용을 다음 질문, 비교표, 계획서에 다시 쓰는 것이다.[6]

이를 위해 요약, 적용 조건, 판단 기준, 한계, 다음 질문을 구분한다.[6]

| 문서의 칸 | 쉬운 뜻 | 다음에 물을 수 있는 질문 |
| --- | --- | --- |
| 한 문장 요약 | 무엇에 관한 문서인가? | 이 작업의 핵심을 설명해 줘. |
| 확인된 내용·근거 | 자료에서 무엇을 알 수 있나? | 어떤 내용이 원문에 있는가? |
| 적용 조건 | 언제 사용할 수 있나? | 우리 팀에도 맞는 방법인가? |
| 판단 기준 | 무엇을 보고 고를까? | 후보 두 개를 비교해 줘. |
| 한계·확인 필요 | 아직 무엇을 모르는가? | 실행 전에 무엇을 확인할까? |
| 다음 질문 | 다음으로 무엇을 알아볼까? | 작은 검토 계획을 만들어 줘. |

표는 원전의 문서 구조를 쉬운 질문으로 풀어 쓴 것이다.[6]

### 제목도 내용을 알려 줘야 한다

`notes.md`보다 `meeting-action-items.md`가 무엇을 다루는지 알기 쉽다. 원전도 파일명과 제목에 주제를 드러내도록 설명한다.[6]

수업에서는 “이 제목만 보고 어떤 질문에 쓸지 알 수 있나?”를 확인한다. 파일명을 길게 만드는 것이 목적은 아니다.

## 3.4 조건 3 — 링크: “이어서 어디를 볼까?”

링크는 다른 문서로 가는 길이다. 근거 자료, 관련 개념, 비교 후보, 위험 기준, 산출물로 이어질 수 있다.[6]

링크가 많기만 하면 좋은 것은 아니다. 다음에 확인할 이유가 있는 문서로 연결해야 한다.[6]

```text
회의 후 할 일 정리
  ├─ 회의 메모 원문       → 실제 발언 확인
  ├─ 초안 검토 기준      → 담당자·기한 오류 점검
  └─ 발표 초안           → 정리한 내용을 활용
```

위 그림은 가상 팀 위키의 연결 예다.

원전은 기본 형식으로 `[문서 제목](파일명.md)` 형태의 표준 Markdown 링크를 사용한다. `[[문서명]]` 링크 지원 여부는 도구에 따라 다르다.[6]

**파일 경로는 링크가 들어 있는 문서 위치에서 계산한다.** 다음 예시가 `wiki/meeting-action-items.md`에 있다면:

- `../raw/team-meeting.md`: 한 단계 위로 올라가 원본 폴더로 간다.
- `review-checklist.md`: 같은 폴더의 검토 기준으로 간다.
- `../output/presentation-draft.md`: 한 단계 위로 올라가 산출물 폴더로 간다.

위 경로는 [앞 문서의 가상 폴더 트리](02-folder-structure.md)에 대한 설명이다. 실제 운영 위키 링크를 생성하거나 확인한 결과가 아니다.

## 3.5 나쁜 메모를 좋은 위키 문서로 바꾸기

### 바꾸기 전: 기대와 사실이 섞인 메모

다음은 일부러 문제를 넣은 수업용 예시다.

```markdown
# 자동화 아이디어

우리 팀은 AI로 회의록을 정리하기로 했다.
정리 시간이 크게 줄어들 것이다.
AI가 담당자와 기한을 알아서 정하면 편하다.
```

문제는 세 가지다.

- 회의 메모의 **검토 제안**을 **도입 결정**으로 바꿨다.
- 측정하지 않은 효과를 확정적으로 기대한다.
- 원문에 없는 담당자·기한을 AI가 만들어도 된다고 해석한다.

### 바꾼 뒤: 근거와 한계를 분리한 정리 노트

아래는 `wiki/meeting-action-items.md`에 들어갈 수 있는 **수업용 가상 문서**다. 실제 생성된 위키 페이지가 아니다.

```markdown
# 회의 후 할 일 목록 정리

## 한 문장 요약

팀은 반복되는 할 일 목록 정리에 AI 초안을 활용할지 검토하려 한다.

## 근거

- 원천 자료: [팀 회의 메모](../raw/team-meeting.md)
- 자료 성격: 수업용 가상 회의 메모
- 근거 위치: 할 일 정리, 활용 제안, 사람 검토, 연락처 제한 항목
- 확인 날짜: 실제 자료를 읽은 날짜를 기록한다.

## 확인된 내용

- 회의 후 할 일 목록을 다시 쓰는 일이 반복된다.
- AI 초안 활용을 다음 회의에서 검토하자는 제안이 있다.
- 정리 결과는 사람이 확인해야 한다.
- 팀원 연락처는 외부 도구에 보내지 않는다.

## 적용 조건과 판단 기준

다음은 원문에서 확정된 결정이 아니라 수업용 검토 제안이다.

- 입력 자료에 할 일, 담당자, 기한이 명시되어 있는지 본다.
- 개인정보를 제외한 허용 자료만 사용한다.
- 사람이 수정하는 시간과 잘못 정리한 항목을 비교한다.
- 담당자나 기한이 없으면 임의로 채우지 않는다.

## 확인 필요

- 실제 도입 여부는 결정되지 않았다.
- 기존 작업 시간과 AI 초안 검토 시간은 측정하지 않았다.
- 어떤 입력 자료를 사용할지 승인받지 않았다.

## 관련 문서

- [초안 검토 기준](review-checklist.md)
- [발표 초안](../output/presentation-draft.md)

## 다음 질문

- 담당자와 기한이 빠진 항목은 어떻게 표시할까?
- 실제 실행 전 확인할 입력 허용 범위와 검토 기준은 무엇일까?
```

핵심은 글을 길게 늘린 것이 아니다. **원문에 있는 내용, 새로 제안한 판단 기준, 아직 모르는 내용을 분리**했다.

## 3.6 문서 점검표

출처·재사용·링크에 더해 한계와 최신성을 점검한다.[6]

- [ ] 중요한 주장에서 실제 원천 자료로 돌아갈 수 있는가?
- [ ] 제안·결정·실행·측정 결과를 구분했는가?
- [ ] 한 문장 요약과 적용 조건이 있는가?
- [ ] 판단 기준과 확인 필요 항목이 있는가?
- [ ] 다음에 물어볼 질문이 있는가?
- [ ] 관련 문서나 산출물로 이어지는 링크가 있는가?
- [ ] 링크 대상이 실제 존재하고 경로가 맞는가?
- [ ] 날짜가 필요한 정보에 확인 날짜가 있는가?
- [ ] 민감 정보 처리와 외부 공유 범위를 확인했는가?

체크리스트를 통과했다고 모든 주장이 참인 것은 아니다. 중요한 내용은 연결한 원문을 직접 대조한다.[6]

### 이해 확인

**Q. 출처 링크만 붙이면 좋은 위키 문서일까?**

출처뿐 아니라 다음 질문에 쓸 구조와 관련 연결도 필요하다.[6]

**Q. “도입 효과는 확인 필요”라고 쓰면 문서가 덜 완성된 것 아닐까?**

모르는 것을 표시해야 다음에 보강할 지점을 알 수 있다. 측정하지 않은 성과를 만들어 쓰는 것보다 안전하다.[6]

> **핵심: 좋은 문서는 ‘어디서 왔는지, 다음에 어떻게 쓸지, 어디로 이어질지’를 보여 준다.**
