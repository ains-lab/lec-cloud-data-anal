# 7주차 — LLM 위키의 기본 구조 쉽게 이해하기

**LLM 위키는 AI가 자료를 읽고 정리하도록 돕되, 원본과 정리본을 구분해서 다음에도 다시 쓰는 지식 관리 방식이다.** 특정 앱 하나의 이름으로 이해하지 않는다.[1]

책상 위에 자료를 쌓아 두는 것과, **원본 보관함·정리 노트·작업 규칙**을 갖춘 책상을 만드는 것은 다르다. 이번 주에는 이 차이를 배운다.

## 대상과 범위

- 대상: LLM을 사용해 본 학부 수강생. 어려운 말은 일상 비유로 먼저 설명한다.
- 형식: `/eli5` 방식의 한국어 개념 노트. 비유 → 역할 → 작은 예시 → 확인 질문 순서로 읽는다.
- 원전: 박승규, 『LLM위키 완벽 가이드』.[2]
- 정리 범위: **2.1 지식이 쌓이는 세 층, 2.2 좋은 폴더 구조 이해하기, 2.3 좋은 위키 문서의 조건**.[3]
- 원문 확인일: 2026-10-12 UTC. 해당 2장 페이지들의 표시 편집일은 2026-05-16이다.[4][5][6]
- 제공된 `https://wikidocs.net/353379`는 **1.2 LLM위키는 무엇인가**다. 배경 설명에 참고하고, 본문은 실제 2장 각 절을 읽어 정리했다.[1][3]
- 수업용 팀 회의 사례와 문제는 이해를 돕기 위해 새로 만든 **가상 예시**다. 실제 회의·수집·모델 실행 결과가 아니다.
- 원문의 본문·표·텍스트로 제공된 도해 설명을 읽었다. 삽화 이미지는 별도로 검토하지 않았다.

## 먼저 기억할 한 장짜리 그림

```text
                  작업 규칙
          원본 보호 · 출처 표시 · 모르면 표시
                    │
                    ▼
원본 보관함 ── 읽고 정리 ──▶ 정리 노트 ── 활용 ──▶ 발표·보고서
   raw/                      wiki/                output/
    ▲                          │                     │
    └──────────── 근거를 확인할 때 돌아가기 ───────────┘

index.md = 어디에 무엇이 있는지 알려 주는 안내판
log.md   = 언제 무엇을 넣고 고쳤는지 남기는 작업 일지
```

2.1절에서 말하는 **세 층은 `raw`, `wiki`, 작업 규칙**이다.[4]
`raw → wiki → output`은 자료가 결과물로 바뀌는 **활용 흐름**이다. `output`을 작업 규칙 대신 세 번째 층으로 외우지 않는다.[4][5]

## 수업을 마치면 할 수 있어야 하는 것

1. 원본 자료, AI가 정리한 문서, 보고서 초안을 구분한다.
2. `raw/`, `wiki/`, `output/`, `index.md`, `log.md`, 작업 규칙의 역할을 설명한다.
3. 원문에서 “검토하자”라고 한 내용을 “결정했다”라고 바꾸면 왜 틀리는지 설명한다.
4. 위키 문서에서 **출처·다시 쓸 수 있는 구조·관련 링크**를 찾는다.
5. 모르는 수치나 결정되지 않은 사항을 `확인 필요`로 남긴다.

## 앞선 수업과 연결하기

[6주차](../6w/README.md)가 “자료를 어떻게 모을까?”를 다뤘다면, 이번에는 “모은 자료와 그 자료를 해석한 문서를 어떻게 구분할까?”를 다룬다. **파일을 저장한 것, 내용을 읽고 정리한 것, 정리 결과를 검증한 것은 서로 다르다.**

[4주차 증분 위키 실습](../4w/07-incremental-wiki.md)의 DB·처리 배치·검증기와 이번 책의 단순 폴더 예시는 같은 구현이 아니다. 이번 자료는 먼저 역할을 이해하기 위한 설명이다.

## 이 폴더와 실제 위키를 혼동하지 않기

- `docs/lectures/7w/`는 **강의 노트 폴더**다. 문서 안의 폴더 트리는 예시이며 실제 운영 위키를 생성한 것이 아니다.
- 이 저장소 루트의 논문 Wiki 정책과 수집 작업은 그대로 둔다. 책에 나온 일반 예시가 기존 원천 자료의 변경·변환·덮어쓰기 허가가 되지 않는다.
- 실제 적용할 때는 대상 위키의 정책과 도구가 읽는 규칙 파일을 먼저 확인한다. 파일명·저장 위치는 구현에 따라 달라질 수 있다.[4][5]
- 이번 작업은 문서 작성이다. 설치, 로그인, 원문 수집, 모델 호출 실습, Cron 등록, 외부 공유는 수행하지 않았다.

## 한 문장 복습

> **원본은 보관하고, 지식은 따로 정리하고, 규칙으로 작업 기준을 남긴다. 정리한 내용에는 원본으로 돌아가는 길을 붙인다.**
